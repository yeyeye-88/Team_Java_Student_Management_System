## 三、查询优化措施

### 3.1 JPA查询优化
1. **LEFT JOIN FETCH** - 避免 N+1 查询问题
   ```java
   @Query(value = "SELECT DISTINCT sl FROM StudentLeave sl " +
          "LEFT JOIN FETCH sl.student s " +
          "LEFT JOIN FETCH s.person sp " +
          "LEFT JOIN FETCH sl.teacher t " +
          "LEFT JOIN FETCH t.person tp " +
          "WHERE ...")
   ```

2. **参数化查询** - 防止SQL注入，提升执行计划缓存命中率

3. **分页查询** - 大数据量时使用分页（由Service层控制）

### 3.2 数据库层面优化
1. **索引覆盖** - 常用查询字段全部建立索引
2. **外键约束** - 保证数据完整性，优化JOIN查询
3. **统计查询优化** - 使用聚合函数减少数据传输

## 六、索引添加截图说明

### 6.1 索引创建方式

**项目使用 JPA `ddl-auto: update` 模式，索引通过以下方式管理：**

1. **JPA 自动生成**: 启动应用时 JPA 自动创建基础索引
2. **手动添加索引**: 在 MySQL Workbench 中执行以下 SQL（可选，JPA 已包含基础索引）

```sql
-- 为学生ID添加索引（JPA已自动创建，此SQL用于验证）
CREATE INDEX idx_student_leave_student_id ON `student_leave`(`student_id`);

-- 为审批状态添加索引
CREATE INDEX idx_student_leave_state ON `student_leave`(`state`);

-- 为申请时间添加索引
CREATE INDEX idx_student_leave_apply_time ON `student_leave`(`apply_time`);

-- 为教师ID添加索引
CREATE INDEX idx_student_leave_teacher_id ON `student_leave`(`teacher_id`);

-- 为请假日期添加索引
CREATE INDEX idx_student_leave_leave_date ON `student_leave`(`leave_date`);
```

**注意**: 这些 SQL 文件已删除，项目不需要手动执行 SQL，JPA 会自动管理表结构和索引。

### 6.2 验证索引生效
```sql
-- 查看表的索引信息
SHOW INDEX FROM student_leave;

-- 查看查询执行计划（验证索引使用）
EXPLAIN SELECT * FROM student_leave WHERE student_id = 10;
EXPLAIN SELECT * FROM student_leave WHERE state = 0;
```
